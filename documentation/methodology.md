# Methodology

This describes the automated peptide modelling pipeline in `pipeline/`, following the two papers that report it (see "How to cite" in the main README):

- **Paper 1:** Kalyan et al., *J. Agric. Food Chem.* 2021, 69, 14995–15004 ("Peptide Model Development").
- **Paper 2:** Kalyan et al., *J. Biomol. Struct. Dyn.* 2021, 39, 635–649 (section 2.1, "Peptide modeling automation").

## Why peptides are modelled from sequence

The 3D structure of a peptide is needed for docking and for structure-based features. Cutting the peptide out of its parent protein structure is not suitable: it keeps the steric strain, bond angles and dihedrals imposed by the surrounding residues, and a peptide free in solution has different degrees of freedom. Drawing each peptide by hand in small-molecule software is slow and error-prone. So each peptide is built from its sequence and then energy-minimised separately.

## The pipeline

Input is one or more peptide sequences. Output is one minimised 3D structure per sequence, in PDB format.

| Step | What happens (as described in the papers) | Script |
|---|---|---|
| 1. Build | The peptide is built from its sequence with PyMOL, through Python scripts that use the PyMOL API (described in the papers as MMFF-based peptide building). The builder gives a structure without terminal groups. | `pipeline/build_peptide.py` |
| 2. Terminal groups | The papers add the terminal groups with a second PyMOL-API script: hydrogen at the N-terminus and a hydroxyl at the C-terminus. In this repository the C-terminal oxygen (`OXT`) is added inside `build_peptide.py`, and the hydrogens are added in step 3. | `pipeline/build_peptide.py` |
| 3. Hydrogens and charges | Chimera adds hydrogens (using hydrogen-bond considerations and the protonation state), then assigns atom types and charges. | `pipeline/chimera-try1.py` |
| 4. Minimise | Chimera runs steepest-descent minimisation followed by conjugate-gradient minimisation. Paper 2 reports the AMBER ff14SB force field for standard residues and GAFF for anything non-standard. | `pipeline/chimera-try1.py` |
| 5. Automate | The build script and the Chimera minimisation script are chained so a list of sequences runs unattended. | `pipeline/pep_model.py` |

Minimising matters because the built structure has idealised bonds, angles and torsions, and the hydrogen positions have not been optimised. Minimisation relaxes these, and it can also resolve close contacts so the peptide reaches a sensible conformation.

**Why Chimera.** The minimisation uses Chimera so that users who do not have GROMACS (or another MD package) installed can still get energy-minimised peptide models.

## What the scripts do

- `build_peptide.py` builds each peptide from `peptides.pf` by attaching residues one at a time with fixed backbone angles (extended conformation by default) and adds the terminal oxygen (`OXT`). It writes `pep_struc/<sequence>.pdb`.
- `chimera-try1.py` opens each of those files in Chimera, runs `addh`, `addcharge` and `minimize`, and writes `<sequence>_minimized.pdb`. It calls `minimize` with Chimera's own settings, so use paper 2 for the force-field setup that was reported.
- `pep_model.py` runs the two steps in order.

Details of every script, including the variants in `capped/` and `fab/`, are in [scripts.md](scripts.md).

## Where the models are used

In the papers the minimised peptides are the ligands for the next steps:

1. **Docking.** Peptides are docked to human ACE (PDB 4APH) with AutoDock Vina, using a 20 × 20 × 20 Å box. The lowest-energy poses are merged with the receptor to give ACE–peptide complexes. These steps are not in this repository.
2. **Simulation.** Selected complexes are simulated with GROMACS (paper 2). Those complex simulations are also not in this repository. `md/` only runs short simulations of single peptides.
3. **Web server.** The AHPP web server (http://hazralab.iitr.ac.in/ahpp/index.php) models peptides generated by in silico digestion in the same way, then computes structure- and sequence-based features for IC50 prediction (paper 1).

Paper 2 saves all sequences and the minimised structures as `.fasta` and `.pdb` files, and the models are further analysed (for example dihedral angles) with the Macromolecular Analysis Toolkit (MAT).
